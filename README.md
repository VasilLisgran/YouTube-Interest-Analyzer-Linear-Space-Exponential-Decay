# YouTube Interest Analyzer: does temporal decay help?

Code, data and raw logs for

> Kalinkin V. A. *Does Temporal Decay Help a YouTube Interest Model? A Rolling-Origin Study with a No-Decay Control.* (manuscript)

A small, interpretable user-interest model over YouTube's 17 content categories:
each liked or watched video adds a duration-derived weight discounted by
`lambda ** age_in_days`. The study tests the decay against an explicit no-decay
control (`lambda = 1.0`) with a rolling-origin evaluation, first on two personal
like histories and then on 76 public watch histories.

## Layout

```
code/        Python analysis pipeline (one script per analysis)
data/        exported like histories: user_videos_u{1,2,3,7}.json  (see data/README.md)
external/    replication on public watch histories: protocol, scripts, results, synthetic check
logs/        raw console output of every script, one file per table/figure source
figures/     Figures 1 and 2 (regenerated by run_all.sh)
client/      Java client: YouTube Data API export, profile, keyword recommendations
demo/        outputs of a demonstration run of the Java client (not used by the paper)
run_all.sh   regenerates the logs; --check compares them with the committed ones
```

## Quick start

Python 3.12 or newer:

```bash
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
./run_all.sh --check        # about a minute; prints OK / DIFF for every log
```

`--check` writes to `outputs/check/` and compares file by file with `logs/`; without
it the script overwrites `logs/` and `figures/`. Every offline step is seeded
(bootstrap seed 0, hash-based tie-breaking) and reproduces the committed logs byte
for byte; this was checked on numpy 2.4.4 / scipy 1.17.1 / scikit-learn 1.8.0 /
matplotlib 3.10.8 (the pinned versions) and on numpy 2.5.3 / scipy 1.18.1 /
scikit-learn 1.9.1 / matplotlib 3.11.2, under Python 3.13. The figures are
regenerated but not compared byte for byte, because PNG output depends on the
installed fonts.

What the offline run covers, and what it cannot:

| Logs | Reproduced from | Offline |
|---|---|---|
| 03-11, 19, 20 | `data/` | yes |
| 14, 15, Figure 2 | `external/results/` (chrono_split.py output of the replication) | yes |
| 16 lines 2-5 | `external/results/` | yes |
| 17, 18 (likes and synthetic lines) | `data/`, `external/synthetic/` | yes |
| 01, 02 | `data/` + LaBSE model | `--labse` (20-60+ min, downloads the model) |
| 13, 18 (watches line) | per-user watch files | `--watch-users DIR` |
| 12, 12b, 16 line 1, 16b | public watch log + YouTube API metadata | manual, see `external/README_external.md` |

Steps 01-02 agree with the committed logs to the printed precision rather than
byte for byte, because of BLAS and threading details. `logs/01b_...json` holds the
per-account values of step 01 (the `per_user` part of the JSON it writes).

The scripts run with `outputs/` as the working directory. It is a sibling of
`code/` and `data/`, so the `../data/...` paths printed inside the logs are valid.

## Data

`data/user_videos_uN.json`: liked-video histories of four consenting account
holders; u2 and u3 are the two that pass the inclusion rules. Schema, consent
and terms of use are in [`data/README.md`](data/README.md).

The public watch-history dataset used for the replication (Lall et al., 2020)
and the video metadata fetched from the YouTube Data API are **not**
redistributed here (the latter because of the API's terms). What is committed is
the output of `chrono_split.py` on the replication users (`external/results/`),
which carries per-user metrics only, and the identifiers of the 82 selected
users. `external/README_external.md` explains how to regenerate everything else.

## Java client (optional)

Only needed to re-export data; the paper's numbers are computed from `data/`.
Requires Java 11+ and Maven (`mvn -f client/pom.xml package`). Run class `Main`
(default package, `client/src/main/java/Main.java`) with the repository root as
the working directory, because the client calls `code/clusters.py` relative to it:

```
Main --user u2 --reference-date 2026-08-26 --lambda 0.95 --max-days 360 \
     --weight ORIGINAL --top 3 --max-searches 20 --out demo
```

It authenticates with your own OAuth client (`client/src/main/resources/client-secret.json`,
git-ignored; credentials are not distributed), exports the liked-video history,
calls `code/clusters.py` for keyword clusters and issues keyword searches. Pass
`--out demo` to keep the committed `data/` untouched.
